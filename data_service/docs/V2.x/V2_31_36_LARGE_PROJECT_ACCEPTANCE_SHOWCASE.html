1. 为什么仍是 accepted_with_blockers

当前状态不是失败，而是可信验收策略：项目已经可以完成大型仓库阅读、任务导航、关系图、影响分析、阅读包和 handoff， 但仍有动态调用、缺少公开入口事实、低证据关系等内容不能被当作确定事实接受。

Blocker 类型 出现原因 当前处理 后续优化方向
DYNAMIC_ATTRIBUTE_CALL_UNRESOLVED AST 能看到属性调用，但无法仅凭静态语法确认运行时接收者、动态分发、插件绑定或类型。 保留为 blocker，不伪装为 runtime call graph。 引入 import resolver、类型提示/LSP、有限调用图、框架规则和人工确认覆盖。
TASK_NAVIGATION_PUBLIC_SURFACES_UNAVAILABLE HarnessOS/codexPat 未被当前 extractor 确认为 HTTP/MCP/CLI public surface 项目。 继续基于 files/symbols/imports/tests/docs 生成阅读结果。 增加泛化入口模式：workflow manifest、TUI/desktop entrypoint、command registry、app route config。
RELATIONSHIP_PUBLIC_SURFACES_UNAVAILABLE 没有 public surface，无法构建 surface-to-handler 关系。 关系图仍输出 import/direct AST/test/config 层关系。 增强非服务型项目的入口识别和文档-代码入口对齐。
RELATIONSHIP_SURFACE_MAPPINGS_UNAVAILABLE 没有 surface，就没有 surface-symbol mapping。 以 blocker 显式说明，不让 closure 假通过。 扩展 mapping 到 workflow step、desktop command、CLI parser、TUI action。

6. 当前项目能否持续优化

优化方向 能解决什么 验收方式
入口识别泛化 让 HarnessOS 类非 HTTP/MCP 项目识别 workflow/TUI/desktop/command registry 入口。 HarnessOS surface_types 从空变为 workflow/console/tui/command，并有源码行证据。
静态关系增强 减少动态属性调用 blocker，提升直接可用关系比例。 blocker count 下降，新增关系必须有 line evidence 且不声称 runtime certainty。
文档-代码双向对齐 把架构设计文档中的模块/流程与代码事实更稳定地匹配。 每个 matched claim 同时有 document evidence 与 code evidence。
报告可读性增强 让人类不用读 JSON，就能理解模块边界、任务影响和阻塞原因。 HTML 报告含多图、热力图、分层关系图、可点击证据链接。
